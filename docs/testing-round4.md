# 2026-10-19 第四轮：离线补丁与一致快照

最终源码在 SSH `linux` 原有 Docker 容器/cgroup 中完成验证，
`fmt/clippy/tests/spec` 状态全部为 0。构建、测试及语料处理均在远端 `/tmp`；本机仅编辑源码和保存 `/tmp` 证据副本。
实际测试的 Cargo 文件、Rust 源码、fixtures 和工具摘要与 checkout 逐项一致。

## 本轮实现

- 新增公共 `wasm_git::patch` API 和 `patch` / `apply` CLI。
  规范 JSON 绑定完整原始文件 SHA-256、长度、两侧物理位置及旧/新字节；
  输入区间、间隙、旧字节和重放结果均校验后才允许发布。
- `apply --check` 返回从验证后字节重新计算的完整审计；补丁不携带可被误信的特性、验证或最小性声明。
  未知指令、无效标准 payload、不透明 custom 与合法非规范 LEB 均原样重放。
- 新文件输出使用同目录独占临时文件写全并同步后，通过 hard link 原子发布且不覆盖已有目标。
  checkout 和 bundle 也复用该工具；竞争失败只清理本操作的临时文件。
- 仓库版 `diff` / `patch` 的两侧 revision 在同一锁和完整验证快照中解析。
  `inspect` / `diff` / `patch` / `apply` 返回实际提交 ID，不仅显示可能变化的引用名。
- 标准 section 后项失败不再丢失此前完整条目的说明和位置；undecoded 覆盖整个失败项起的后缀，
  不按 decoder 内部报错位置遗漏已消费字节。坏 import 后的全局 function index 明确为 unknown。
- 未知 Core section 导致函数投影不可用时，诊断不再误称 Component Model。
  CLI help 成功退出，缺参数仍保持原有错误提示契约。

协议、原子发布的失败边界及命令用法见[补丁说明](patch.md)。
`--check --repo` 仍会短暂创建仓库锁；它不修改对象、引用或输出文件，并非零文件系统写入。
