# 按字节区间查询历史影响

`trace` 从一个固定提交中的原始字节区间出发，沿提交 DAG 的全部父边查询相关编辑与影响范围。
它提供可复核的物理证据，不把相同字节、函数索引或名称解释成唯一的历史身份，也不归属作者。

```sh
wasm-git inspect HEAD --repo ./history --json
wasm-git trace ./history HEAD --path 'code[0]/function[0]'
wasm-git trace ./history HEAD --range 40:48
wasm-git trace ./history HEAD --path module --max-edges 64 --max-bytes 8388608
```

`--path` 精确选择起点提交中的审计 section 或 region 路径，`module` 表示整个文件。
`--range` 使用十进制 ASCII 字节偏移与半开区间 `[start,end)`，必须非空且处于起点文件范围内。
二者必须选一个且不能同时使用。路径只用于选定起点区间，不在祖先中按同名路径猜测对象身份。
空区间、空 region、反向或越界范围、未知或多义路径均拒绝。

输出为 JSON，`selection` 保存起点区间，`trace.tip` 为实际提交 ID。
无论是完整结果还是预算范围内的部分结果，只要查询成功，退出码均为 0；
调用者必须检查 `trace.complete` 和 `trace.frontier`。输入或仓库错误退出码为 1。
`frontier` 中的 `root_snapshot` 和 `introduced_no_old_bytes` 是正常终点；预算或对齐回退原因才表示未完成的继续查询。
`--help` 成功退出，不读取仓库。

## 三种范围状态

查询表达的是审计编辑脚本下的历史影响，整个报告始终标注 `identity_unproven=true`。

| scope | 含义 |
|---|---|
| `requested` | 起点提交中明确选定的字节 |
| `aligned` | 沿已核对相等字节的未变间隙映射得到的位置 |
| `influence` | 相关替换或删除所关联的整个旧编辑块，以及其后续历史影响 |

每条父→子边独立比较完整原始文件，并保留 `exact_minimal`、`alignment`、验证状态和解码诊断。
最短编辑脚本也可能存在多种最优对齐；`aligned` 只证明此脚本中的字节相等，不证明唯一来源。
一旦范围扩展为 `influence`，穿过更早的未变间隙也不会恢复为确定的身份。

- 未变间隙：只按实际偏移平移命中的片段，并核对两侧片段逐字节相同。
- 替换：报告完整原始编辑和命中片段；继续查询整个旧编辑块，不把块内相同相对偏移配成来源。
- 插入：旧区间为空，报告 `introduced_no_old_bytes`；该新增片段终止旧侧追踪。
  这表示所选脚本没有对应的旧字节，不证明内容首次创作，也不自动跟随复制或搬移。
- 删除：新区间为空，单列 `boundary_touch` 事件。
  删除锚点落在查询的闭边界 `[start,end]` 时报告，包括恰好位于起点、终点及 EOF 的情形；
  它是邻接边界事件，不能解释成当前字节的来源。旧删除块可作为 `influence` 继续查询。

每个相关事件保留 `ByteEdit` 的两侧原始区间、hex 和上下文。
同一节点收到多个路径的范围时先汇总再处理，重叠范围可合并，但不会用包围区间填补未查询的间隙。
多父提交保留所有父边和父列表原有顺序；不能根据相对某一个父节点的差异判断合并提交“创作”了哪些字节。
根提交只标记为 `root_snapshot`，不表示已经找到真实创作起点。

## 停止边界与预算

当某条比较进入有界 diff 的回退路径，仍展示该边已得到的相关编辑和映射证据，
但以 `alignment_fallback` 停止该边向更早历史传播，并将 `complete` 置为 false。
不会把大型旧模块的整块替换直接宣称为某段内容的来源。

默认工作预算：

| 项目 | 默认上限 |
|---|---:|
| 父边处理 | 256，可用 `--max-edges` 调整 |
| 比较的输入字节累计 | 64 MiB，可用 `--max-bytes` 调整 |
| 每个提交的范围数 | 1,024 |
| 证据记录累计 | 16,384 |

预算在整个 DAG 中共享，不因分支或祖先重置。相同 blob 对的比较结果可复用，
缓存命中仍消耗父边预算，但不重复消耗输入字节比较预算。
证据记录计数覆盖映射、事件及命中、诊断和父侧范围；控制节点、停止说明和 frontier 不计入该计数，
以便零预算时仍能说明未处理的工作。
预算耗尽会返回已完成证据与明确 frontier，不会把未查询历史当作未变化、插入或起源。

`complete=true` 只表示本次选定影响范围按上述规则到达根快照或旧侧为空的边界，
没有因工作预算或对齐回退而遗漏继续查询的任务。它不证明函数历史身份、最优对齐唯一性或行为等价。

## 快照与未知内容

仓库先在同一锁中验证完整对象库、引用及父链，固定目标提交，再取出其全部可达祖先。
相同 Wasm blob 只复制一次；无关分支和未引用对象不会作为查询证据，但其损坏仍使仓库校验失败。
释放锁后，查询使用已复制的不可变数据，其他提交不会改变本次输入。

查询不修改对象、引用或历史，但读取快照时仍短暂创建和删除 `.uwgit/write.lock`，需要仓库可写且未被其他操作锁定。
工作预算不限制现有仓库快照的读取内存；快照仍加载并校验整个对象库。
快照加载、输入图校验和起点路径解析也不计入输入字节比较预算。

未知 opcode、未知 section、不透明 custom 和合法非规范 LEB 都按原始字节参与历史比较，
不会要求函数分析或模块验证成功。Component Model 不在仓库接受范围内。
公开 `wasm_git::trace` API 校验输入图的结构，仓库对象摘要认证由仓库读取层负责。
